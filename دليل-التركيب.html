التركيب على Windows Server

1 تركيب Python

نزّل Python 3.13 من python.org/downloads

أثناء التركيب فعّل خانة Add Python to PATH في أول شاشة. نسيانها هو السبب الأول لفشل التركيب.

2 نسخ ملفات النظام

فُكّ الضغط عن الملف في مسار ثابت، مثل C:\AseerHR

تجنّب المسارات التي تحوي مسافات أو حروفاً عربية.

3 توليد المفتاح السري

افتح موجّه الأوامر (Command Prompt) داخل مجلد النظام واكتب:

python generate_key.py

سيظهر سطر يبدأ بـ DJANGO_SECRET_KEY= — انسخه كاملاً.

4 إعداد ملف الإعدادات

  1. انسخ الملف .env.example وسمِّ النسخة .env
  2. افتحه بـ Notepad
  3. الصق المفتاح مكان السطر DJANGO_SECRET_KEY=
  4. اكتب عنوان الخادم في DJANGO_ALLOWED_HOSTS

مثال إن كان عنوان الخادم 10.0.0.15:

DJANGO_ALLOWED_HOSTS=10.0.0.15
اكتب العنوان فقط — بلا http:// وبلا / في النهاية. الخطأ هنا يجعل النظام يرد برسالة Bad Request (400) على كل الطلبات.

5 تشغيل التركيب

افتح مجلد tools وشغّل بالنقر المزدوج:

1-تركيب-النظام.bat

انتظر حتى تظهر رسالة «تم التركيب بنجاح».

6 إنشاء حساب المدير

2-إنشاء-حساب-مدير.bat

سيطلب اسم مستخدم، ثم بريداً، ثم كلمة مرور مرتين.

كلمة المرور لا تظهر أثناء الكتابة — لا حروف ولا نجوم. هذا طبيعي، أكمل الكتابة واضغط Enter.

7 تشغيل النظام

3-تشغيل-النظام.bat

اترك النافذة مفتوحة. النظام الآن يعمل.

8 فتح النظام من أجهزة الموظفين

من أي متصفح داخل الشبكة:

http://10.0.0.15:8000

استبدل العنوان بعنوان خادمك.

التركيب على Linux

cd /opt/aseer-hr
cp .env.example .env
python3 generate_key.py        # انسخ الناتج إلى .env
nano .env                      # عدّل المفتاح والعنوان

bash tools/install.sh
venv/bin/python manage.py createsuperuser
bash tools/run.sh

التشغيل التلقائي عند إقلاع الخادم

sudo cp tools/aseer-hr.service /etc/systemd/system/
sudo nano /etc/systemd/system/aseer-hr.service   # عدّل المسار والمستخدم
sudo systemctl daemon-reload
sudo systemctl enable --now aseer-hr
sudo systemctl status aseer-hr

فتح المنفذ في جدار الحماية

إن لم يفتح النظام من أجهزة أخرى، فالمنفذ 8000 مغلق:

Windows

netsh advfirewall firewall add rule name="Aseer HR" ^
  dir=in action=allow protocol=TCP localport=8000

Linux

sudo ufw allow 8000/tcp

ملاحظة أمنية يجب إبلاغ العميل بها

النظام يعمل افتراضياً على HTTP بلا تشفير. هذا يعني أن كلمات المرور وبيانات الموظفين تمرّ على الشبكة الداخلية بنص مقروء، ويمكن لمن يملك وصولاً للشبكة أن يلتقطها.

مقبول داخل شبكة معزولة وموثوقة. وإن أمكن تركيب شهادة SSL، غيّر DJANGO_SECURE_SSL=True في .env وأعد التشغيل. لا تفعّله قبل تركيب الشهادة وإلا تعطّل الدخول تماماً.

قاعدة البيانات

النظام يستخدم SQLite افتراضياً — ملف واحد اسمه db.sqlite3 داخل مجلد النظام. لا يحتاج أي تركيب إضافي، ويكفي تماماً حتى بضعة آلاف موظف وعشرات المستخدمين.

الأهم: ملف db.sqlite3 هو كل بياناتك. فقدانه يعني فقدان كل شيء. راجع دليل التشغيل لجدولة النسخ الاحتياطي.

للانتقال إلى PostgreSQL لاحقاً (عند تجاوز عشرات المستخدمين المتزامنين)، اكتب في .env:

DATABASE_URL=postgres://user:password@127.0.0.1:5432/dbname
